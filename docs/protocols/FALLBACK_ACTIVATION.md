# Fallback activation rule

Activate a fallback only when a primary checkpoint is inaccessible after a documented access attempt; its license prevents the intended research use; its architecture cannot support the frozen intervention; a full-precision cloud pilot exceeds available memory; or reproducible execution requires inaccessible custom code. The trigger must be recorded before scientific outcomes are inspected.

Do not activate a fallback because of a null result, a smaller/larger effect, an uninteresting curve, or a preferred behavioral outcome. The fallback inherits the same direction, leakage, site, scoring, and claim-boundary rules; it does not create a new unconstrained experiment.
